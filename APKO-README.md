# Build System: melange + apko

This document covers the Wolfi-native build pipeline used to produce the Azure DevOps agent image. For running the agent, see [README.md](README.md).

## Overview

The build uses two Chainguard tools:

- **[melange](https://github.com/chainguard-dev/melange)** — builds `azdo-agent-tools` as a signed APK package. Downloads all tool binaries (kubectl, kubelogin, terraform, vendir, kluctl), verifies each with SHA256, and installs `start.sh` to `/azp/`.
- **[apko](https://github.com/chainguard-dev/apko)** — assembles the final OCI image from Wolfi APK packages. No Dockerfile is used at image assembly time.

Azure CLI is installed as the Wolfi `az` APK (signed by the Wolfi repository key) rather than via pip, giving it the same supply chain assurance as all other packages.

## Files

| File | Purpose |
|---|---|
| `melange.yaml` | APK package spec — version variables, SHA256-verified binary downloads, `start.sh` install |
| `apko.yaml` | Image assembly config — package list, user/group, entrypoint, environment variables |
| `build-apko.sh` | One-command local build wrapper using pinned Chainguard container images |
| `update-checksums.sh` | Fetches and updates SHA256 pairs in `melange.yaml` after a version bump |
| `melange.rsa.pub` | Public signing key for the local APK repository (committed) |
| `melange.rsa` | Private signing key — **gitignored, never commit** |

## Local Build

Requires Docker with privileged mode (melange uses bubblewrap for namespace isolation).

```bash
# Build: generates signing key if absent, then runs melange → index → apko
./build-apko.sh

# Load the image
docker load -i azdo-agent-apko.tar

# Verify all tools
docker run --rm --entrypoint /bin/bash azdo-agent:apko-amd64 -lc '
  kubectl version --client
  az version
  terraform version
  vendir --version
  kluctl version
  melange version
'
```

> After `docker load`, the tag gains an arch suffix: `azdo-agent:apko-amd64`.

### Build output

```
packages/x86_64/azdo-agent-tools-<version>-r0.apk   # signed APK package
packages/x86_64/APKINDEX.tar.gz                      # signed repository index
azdo-agent-apko.tar                                   # OCI image tar
sbom-*.spdx.json                                      # SBOM (generated by apko)
```

## CI Pipeline

`.github/workflows/build.yml` runs on every push and PR to `main`:

1. Install melange via `chainguard-dev/actions/setup-melange@v1.6.8` (native binary on runner)
2. Install apko from its GitHub release binary (pinned via `APKO_VERSION`)
3. `melange keygen` — fresh ephemeral signing key per run
4. `melange build --arch amd64` — builds `azdo-agent-tools` APK
5. `melange index` — signs the APK repository index
6. `apko build --arch amd64` — assembles OCI image
7. `docker load` + tool version checks — verifies the image works

> melange and apko run as native binaries on the GitHub Actions runner (not inside their distroless container images). The distroless apko image has no shell and cannot be used directly on GitHub Actions runners. The local `build-apko.sh` script uses the container images with `@sha256` digest pins for reproducible local builds.

**arm64 build** is commented out in the workflow. Re-enable by uncommenting the QEMU setup step, the `aarch64` index step, and the arm64 verify step in `build.yml`.

## Releases

`.github/workflows/release-please.yml` reads conventional commits and opens a release PR automatically. When merged, it tags and creates a GitHub release. `.github/workflows/publish.yml` then fires on the `release: published` event and uploads:

- `azdo-agent-apko.tar` — OCI image
- `azdo-agent-tools-*.apk` — signed APK package
- `APKINDEX.tar.gz` — signed APK index
- `sbom-*.spdx.json` — SBOM files

## Signing Key Management

The private key is generated locally with `melange keygen` and gitignored. The public key (`melange.rsa.pub`) is committed and referenced by `apko.yaml`.

```bash
# Regenerate (if lost or rotating)
melange keygen
git add melange.rsa.pub
git commit -m "chore: rotate melange signing key"
```

CI generates a fresh ephemeral keypair on every run — release builds are not signed with the local key.

## Updating Tool Versions

Renovate automatically opens PRs when upstream versions change. After merging a Renovate PR, SHA256 checksums must be refreshed before the melange build will pass:

```bash
./update-checksums.sh
git add melange.yaml
git commit -m "chore: update checksums for <tool> <version>"
```

The same version must be updated in three files to stay in sync:

| File | What to update |
|---|---|
| `melange.yaml` | `TOOL_VERSION=X.Y.Z` variable + SHA256 pairs |
| `apko.yaml` | `environment:` entry |
| `Dockerfile` | `ENV TOOL_VERSION=X.Y.Z` |

Azure CLI (`az`) is a Wolfi APK — update `az~=X.Y.Z` in `melange.yaml` and `ARG AZCLI_VERSION=~X.Y.Z` in the Dockerfile.
